# ПЕРЕДАТОЧНЫЙ ПАКЕТ — ПОЛНАЯ СПЕЦИФИКАЦИЯ

> **Для Storyboard Studio.** Этот документ описывает **формат** (РЕФЫ БЛОКА, ГЕОМЕТРИЯ и т.д.), но в Studio передаточный пакет — это **внутренний user-prompt агента Seedance Writer**, а не артефакт который копирует пользователь. Сам формат остаётся тот же — меняется только кто его «читает»:
> - **Раньше** (Claude.ai на сайте, ручной пайплайн): пользователь копировал текстовый пакет в новый чат, и Opus в чате читал его как user message.
> - **Теперь** (в Studio): `SeedancePipelineThread` собирает те же данные (карта блока + ГЕОМЕТРИЯ + Bible + рефы + голосовые профили) в user-prompt и передаёт через `claude -p` в Opus как агент. Опус возвращает готовый Seedance промпт, Studio пишет его в `output/seedance/<ep>_block_N.txt` и показывает в попапе по клику кнопки «🎬 Промпт Seedance» на блоке.
>
> **Спецификация формата ниже актуальна для обоих режимов.** Код агента Seedance (`agents/seedance_prompts.py`) ссылается на этот документ как контракт входных данных.

## Зачем нужен пакет

После того как готовы:

1. Монтажная карта
2. Промпты сторибордов (Nano Banana)
3. Сами сториборды (картинки)

— наступает этап генерации видео в Seedance. Промпты Seedance пишутся в отдельном чате, в пакетном режиме, без прикреплённого сториборда (сториборд приходит как `@image1`, но без визуального доступа модель его «не видит»). Чтобы новый чат получил весь контекст одним сообщением — собирается **передаточный пакет**.

Это **plain text** документ (не JSON, не YAML), который копируется автором в чат с Opus и вызывает генерацию китайских промптов Seedance для всех блоков сразу.

## Когда генерируется

После вывода промптов сторибордов автор пишет «да» на вопрос «Сделать передаточный пакет для Seedance?». Тогда генерируется пакет.

## Структура пакета — строго в этом порядке

```
========================================
ПЕРЕДАТОЧНЫЙ ПАКЕТ — [НАЗВАНИЕ СЕРИИ]
========================================

РЕФЕРЕНСЫ СРЕДЫ:
РЕФ N (imgN) — [Название]: [одна строка описания]

РЕФЕРЕНСЫ ОБЪЕКТОВ:
РЕФ N (imgN) — [Название]: [одна строка описания]

ПЕРСОНАЖИ:
- [Имя] (imgN)

ВАЖНО: одежду и внешность персонажей в промптах НЕ описывать — всё берётся из референсов.
ВАЖНО ДЛЯ SEEDANCE: Референс среды прикрепляется как отдельный @image в каждом блоке где эта локация присутствует. Сториборд блока ВСЕГДА @image1.
ВАЖНО: Строки ГЕОМЕТРИЯ в монтажной карте переводятся на китайский и вставляются в блок 动作 каждого шота — это критично потому что в пакетном режиме Seedance пишется в отдельном чате без прикреплённого сториборда.

МОНТАЖНАЯ КАРТА:
[Полная монтажная карта со всеми блоками. Для каждого блока ОБЯЗАТЕЛЬНО строка РЕФЫ БЛОКА сразу после заголовка.]

========================================
КОМАНДА ДЛЯ OPUS: Пакетный режим. Все референсы подтверждены.
Напиши промпты для Seedance 2.0 для всех блоков одним сообщением.
Используй строки ГЕОМЕТРИЯ для блока 空间布局 в каждом шоте с 2+ персонажами.
Перед каждым китайским промптом выводи внешнюю легенду тегов.
========================================
```

## Ключевые элементы — детально

### 1. Строка РЕФЫ БЛОКА (главная новинка пакета)

Идёт сразу после заголовка каждого блока в монтажной карте. Перечисляет ВСЕ `@image` теги нужные в этом конкретном блоке.

**Формат:**

```
РЕФЫ БЛОКА: Сториборд (image1), img2 (ресторан), img3 (бокал вина), img4 (Виктор), img5 (Хлоя)
```

**Порядок строго:**

1. Сториборд (всегда `image1`)
2. Реф среды этой локации
3. Все объектные рефы которые физически присутствуют в сценах блока
4. Все персонажи которые появляются в блоке (лицо видно хотя бы в одном шоте)

**Правила:**

- Если объект физически присутствует в любой сцене блока — он **ОБЯЗАН** быть в строке РЕФЫ БЛОКА.
- Персонаж включается ТОЛЬКО если его **ЛИЦО видно** хотя бы в одном шоте блока. Если в кадре только рука/плечо/запястье без лица — реф персонажа НЕ включается. Часть тела рисуется по анатомическому описанию (мужская/женская рука, рукав пиджака) без тега `@image`.
- Эта строка — прямое задание на блок `参考说明` в китайском промпте Seedance. Каждый `img` из РЕФЫ БЛОКА получает ПОЛНЫЙ блок описания в `参考说明` (см. раздел 1.1 инструкции Seedance v.4.0). Сокращения запрещены.

### 2. Строка ГЕОМЕТРИЯ (вторая главная новинка)

Идёт под каждой сценой где 2+ персонажа. Источник — монтажная карта (она уже содержит эти строки). Сохраняется в пакете дословно.

**Формат:**

```
- Сцена 5 (4 сек) — Макс брезгливо произносит реплику. Реплика: "Let's go to the bedroom."
  ГЕОМЕТРИЯ: Макс — стоит у левого подлокотника дивана, тело повёрнуто к креслу, левая часть кадра средний план. Артур — сидит в инвалидном кресле центр комнаты, неподвижен лицом вперёд, правый нижний угол расфокусированный передний план. Анна — стоит справа от Артура, тело повёрнуто к Максу.
```

**Три координаты на каждого персонажа:**

1. К чему привязан (опирается на, сидит на, стоит у — с указанием якорного объекта)
2. Куда повёрнуто тело/голова
3. В какой части кадра (левая/центральная/правая, передний/средний/задний план)

**Зачем это в пакете:** В пакетном режиме Seedance промпт пишется в чате без сториборда. Сама картинка сториборда у Opus есть как `@image1`, но композиция считывается с неё нестабильно. ГЕОМЕТРИЯ — это страховка: текстовое описание композиции, которое переводится на китайский и идёт в блок `空间布局` каждого шота.

## Алгоритм сборки пакета

```
1. Берёшь финальную монтажную карту (после правок и проверки чекером)
2. Для каждого блока добавляешь строку РЕФЫ БЛОКА сразу после заголовка
3. Проверяешь что строки ГЕОМЕТРИЯ сохранены под всеми сценами с 2+ персонажами
4. Сверху добавляешь блоки РЕФЕРЕНСЫ СРЕДЫ / РЕФЕРЕНСЫ ОБЪЕКТОВ / ПЕРСОНАЖИ
5. Добавляешь блок ВАЖНО (три предупреждения)
6. Снизу добавляешь блок КОМАНДА ДЛЯ OPUS
7. Оборачиваешь в === заголовок и === концовку
```

## Что делает Opus получив пакет

1. Читает РЕФЕРЕНСЫ — понимает что есть в проекте
2. Для каждого блока:
   - Берёт строку РЕФЫ БЛОКА → переводит в блок `参考说明` (полное описание каждого тега по правилам раздела 1.1 инструкции Seedance)
   - Берёт строку ГЕОМЕТРИЯ → переводит на китайский → вставляет в блок `空间布局` каждого шота с 2+ персонажами
   - Перед китайским промптом выводит внешнюю легенду тегов (раздел 1.2 инструкции Seedance)
3. Выдаёт готовые китайские промпты для всех блоков одним сообщением

## Реализация в проекте

Никакого кода писать не надо. Это **plain text протокол** передачи между двумя чатами Claude. Реализация = генерация текста по шаблону выше. Сборщик пакета = функция в Claude которая запускается когда автор подтверждает готовность сторибордов.
