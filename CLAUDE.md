## ⚠️ ВАЖНО — АРХИТЕКТУРА «СЕРИАЛЫ»

Storyboard Automation работает с **множеством сериалов**. Каждый сериал — отдельная
папка внутри `shows/`. Активный сериал записан в `current_show.json`:

```
storyboard-automation/
├── current_show.json           ← {"current": "<slug>"}
└── shows/
    ├── the_last_plan/          ← один сериал
    │   ├── refs/
    │   ├── output/
    │   ├── scenarios/
    │   └── episodes.json       ← названия эпизодов и блоков
    └── (другие сериалы)
```

`shows/` и `current_show.json` в `.gitignore` — НЕ пушатся на GitHub. У каждого
пользователя свои сериалы локально.

### При запросе «работаем над новым сериалом»

1. Спроси у пользователя название сериала (на русском).
2. Сделай slug (латиница, lowercase, подчёркивания) — например `the_last_plan` или
   `prizrak`. Если пользователь не назвал slug сам, сгенерируй из транслита.
3. Создай структуру:
   ```
   shows/<slug>/
   ├── refs/locations/
   ├── refs/characters/
   ├── refs/objects/
   ├── output/prompts/
   ├── output/storyboards/
   ├── scenarios/
   └── episodes.json   (пустой объект {})
   ```
4. Запиши `current_show.json` → `{"current": "<slug>"}` (это переключит активный сериал).
5. Сообщи пользователю: «Сериал создан. В Storyboard Studio он появится в дропдауне».

### При работе над эпизодом

1. По окончании монтажной карты ОБЯЗАТЕЛЬНО допиши в
   `shows/<активный>/episodes.json` название эпизода + имена и описания
   шотов всех блоков. Формат:
   ```json
   {
     "ep20": {
       "title": "Тюремное свидание",
       "blocks": {
         "1": {
           "name": "Встреча у стекла",
           "shots": {
             "1": "Лора сидит на стуле в тюремной форме, ждёт",
             "2": "Виктор входит со стороны посетителей",
             "3": "Оба тянутся к трубкам на стенах"
           }
         },
         "2": { "name": "...", "shots": { "1": "...", "2": "..." } }
       }
     }
   }
   ```
2. **Описания шотов — на языке пользователя** (определять по тому, на каком
   языке юзер общается с тобой в этом чате). Если пишет по-русски — пиши
   по-русски. По-украински — пиши по-украински. По-английски — по-английски.
   Это работает автоматически: одна строка на один язык, ту что использует юзер.
   Storyboard Studio покажет их как есть под карточками шотов.
3. Описания должны быть КОРОТКИЕ (1 строка, до ~15 слов): кто что делает, состояние.
   Без англицизмов, без технических терминов промпта (camera angle, framing).
4. Storyboard Studio читает эти имена для шапок («ВСТРЕЧА У СТЕКЛА ~8с»)
   и текстов под шотами. Без записи в `episodes.json` блок будет показан
   как «БЛОК 1», а под шотом будет английская строка из аннотации промпта.

**Старый формат `"1": "Встреча у стекла"` (только имя блока, без shots)**
тоже поддерживается для обратной совместимости — но используй только новый
с `name` + `shots` чтобы юзер видел описания.

### Язык интерфейса vs язык описаний

Это два РАЗНЫХ слоя — не путай:

**1. Язык интерфейса Storyboard Studio** (табы, кнопки, статус, диалоги) —
переключается в шапке программы кнопкой 🇷🇺 РУС / 🇺🇦 УКР / 🇬🇧 ENG. UI-строки
переведены через `TRANSLATIONS` в `storyboard_app.py`. К `episodes.json` отношения НЕ имеет.

**2. Описания шотов и название эпизода в `episodes.json`** — пишутся ОДНОЙ
строкой на ОДНОМ языке (на котором юзер с тобой говорит в чате). Никаких
dict-объектов с переводами писать НЕ надо — это лишняя работа и риск ошибиться.

```json
"shots": {
  "1": "Лора сидит истощённая, ждёт"
}
```

Что бы ни выбрал юзер в переключателе языка интерфейса — описания останутся
такими, какими ты их написал (на языке его чата). Это правильно: каждый юзер
работает в своём сериале и пишет тебе на своём языке. Сотрудник-украинец
создаст СВОЙ сериал и напишет тебе по-украински → ты ему по-украински напишешь
описания → у него под шотами будет по-украински.

**Многоязычный dict-формат** (`{"ru": ..., "uk": ..., "en": ...}`) технически
поддерживается приложением для обратной совместимости, но НЕ используй его —
кроме случаев когда юзер ЯВНО просит «добавь все три перевода».

### Активный сериал — где смотреть

- `current_show.json` в корне проекта.
- Все CLI-скрипты (`pipeline.py`, `generate_storyboards.py`) автоматически читают
  активный сериал и работают с его `shows/<slug>/refs/` и `output/`.

## ШАГ 1 — КОГДА ПОЛУЧИЛ СЦЕНАРИЙ

Сначала проверь, какой сериал активен (читай `current_show.json`).
Если сериала нет — спроси пользователя, в каком сериале работать (или предложи создать новый).

Затем читай сценарий:
- Какие локации в сценарии
- Какие объекты появляются в **2 и более шотах** (правило ≥2 шотов — для них нужен реф)
- Какие персонажи задействованы

Затем проверяй папки **активного сериала**:
- `shows/<активный>/refs/locations/` — есть ли картинка для каждой локации
- `shows/<активный>/refs/objects/` — есть ли картинка для каждого объекта-в-≥2-шотах
- `shows/<активный>/refs/characters/` — есть ли папка и файл для каждого персонажа

Затем ОСТАНОВИСЬ и напиши пользователю **полный** список с маркерами `✓`/`✗`
по каждому пункту. **Формат СТРОГИЙ** — Storyboard Studio парсит его и
показывает кнопки автоматической генерации.

### Формат ответа (точно так)

```
ЭПИЗОД 21: ТРОЙНОЕ ДНО
Сценарий: <одна короткая строка про что эпизод>

ЛОКАЦИИ:
- ✓ prison_visitation — реф есть (refs/locations/prison_visitation.jpg)
- ✗ prison_phone_hallway — рефа нет, буду генерировать [[GEN:location:prison_phone_hallway:Тюремный коридор с настенными телефонами-автоматами и бетонными стенами]]
- ✗ david_construction_office — рефа нет, буду генерировать [[GEN:location:david_construction_office:Кабинет Дэвида в офисе на стройке: дорогой стол, большое окно с видом на стройку]]

ПЕРСОНАЖИ:
- ✓ Лора — реф есть (refs/characters/laura/laura_prison_grey.jpg)
- ✓ Дэвид — реф есть (refs/characters/david/david_checkered_shirt.jpg)
- ✗ Виктор — рефа нет! Создай через вкладку «Актёры» → «Создать референс»

ОБЪЕКТЫ (правило ≥2 шотов):
- ✗ prison_payphone_wall — нужен реф (появляется в сценах 1, 6, 9, 13) [[GEN:object:prison_payphone_wall:Настенный таксофон с трубкой, крупный план, чёрный пластик]]
- ✗ david_smartphone — нужен реф (появляется в сценах 2, 3, 5, 8) [[GEN:object:david_smartphone:Современный смартфон Дэвида на белом фоне, чёрный корпус]]

Жду команды и начинаю с веб-поиска для prison_phone_hallway и david_construction_office.
```

### Жёсткие правила формата (НЕ нарушать)

1. **ОБЯЗАТЕЛЬНО** перечислить **КАЖДЫЙ** пункт отдельной строкой с
   `✓` или `✗`. **ЗАПРЕЩЕНО** заменять список фразами вроде «Manifest
   записан», «Все рефы готовы», «Локации в наличии», «Вкладка
   РЕФЕРЕНСЫ покажет всё нужное», «Видно в episodes.json». Юзеру
   нужен **видимый** список ПЕРЕД работой — он кликает кнопки рядом
   с конкретными `✗` строками. Без списка кнопок не будет.

   **КРИТИЧНО:** список выводится **ВСЕГДА** при первом ответе на
   запуск эпизода. ДАЖЕ ЕСЛИ:
   - запись эпизода уже есть в `episodes.json` от прошлого прогона,
   - все рефы уже на месте (в этом случае все строки `✓`, маркеров
     не будет, но список всё равно покажи),
   - юзер просто перезапустил тот же сценарий — список снова.

   Кнопки в Studio висят на `[[GEN:...]]` маркерах в текущем сообщении,
   а не на данных в `episodes.json`. Без свежего списка с маркерами
   юзер не сможет ничего сгенерировать.
2. Каждая `✗` строка локации/объекта **ОБЯЗАТЕЛЬНО** должна
   содержать встроенный маркер `[[GEN:type:name:description]]`:
   - `<type>` = `location` или `object` (нижний регистр).
   - `<name>` = slug папки (snake_case, ASCII): `prison_phone_hallway`,
     `david_smartphone`. Без расширения `.jpg`.
   - `<description>` = одна фраза до ~150 символов на русском или
     английском, без переноса строк, без символа `]`. Это контекст
     для фоновой генерации.
3. Для **персонажа** маркер НЕ ставится — рефы персонажей создаются
   через вкладку «Актёры» (другой пайплайн с фото актёра).
4. Если реф **есть** (`✓`) — маркер НЕ ставится.
5. Storyboard Studio скрывает маркер из видимого текста (юзер видит
   только `- ✗ <name> — рефа нет, буду генерировать`) и показывает
   рядом с этой строкой кнопку «🎨 Сгенерировать <name>».
   Юзер кликает кнопку → автономный фоновой агент делает веб-поиск,
   пишет промпт, запускает `pipeline.py generate`, описывает геометрию.
   Юзер в чате параллельно работает.
6. **ОБЯЗАТЕЛЬНОЕ окончание ответа** — последняя строка формата
   «Жду команды и начинаю с <следующий шаг>». Без неё юзер не
   понимает что должно произойти при подтверждении.

### НЕ запускай pipeline пока юзер не подтвердил

- НЕ начинай веб-поиск, НЕ запускай pipeline.py, НЕ пиши промпты
  пока пользователь не сказал «поехали» / «всё верно» / «продолжай»
  ИЛИ не нажал кнопку «🎨 Сгенерировать» рядом с пунктом.
- Кнопки в Studio — это и есть подтверждение для **отдельного**
  пункта. Можно генерировать по одному, не дожидаясь общего «поехали»
  для всех.

## ШАГ 2 — ПОСЛЕ КОМАНДЫ "ПОЕХАЛИ"

Запускай pipeline по этапам:

### ЭТАП 1 — ЛОКАЦИИ

КРИТИЧЕСКИ ВАЖНО: генерацию локаций делать ТОЛЬКО через pipeline.py.
ЗАПРЕЩЕНО писать промпты для локаций самостоятельно без запуска pipeline.py.
ЗАПРЕЩЕНО генерировать локации без предварительного веб-поиска.

Для каждой локации которой нет в refs/locations/:

1. СНАЧАЛА — веб-поиск (сам, без API). Найди как выглядит эта локация в реальности.
   После поиска ОБЯЗАТЕЛЬНО вывести в чат:
   ---
   ЧТО НАШЁЛ В ИНТЕРНЕТЕ:
   Источники: [список сайтов/статей]
   Ключевые детали: [что именно взял для промпта — положение объектов, материалы, свет]
   Промпт для генерации: [точный текст промпта который пойдёт в Fast Gen AI]
   ---

2. ПОТОМ — запустить pipeline.py для генерации картинки:
   python pipeline.py generate [name] "[prompt]"

3. ПОТОМ — отдельным шагом прочитать картинку через Read file 
   и показать пользователю. Read file должен быть отдельным 
   действием — не внутри блока с другими командами.
   ЗАПРЕЩЕНО писать путь к картинке текстом — только Read file.

4. ПОТОМ — самостоятельно описать геометрию локации на основе увиденной картинки
   (БЕЗ вызова Anthropic API — ты уже видишь картинку в чате)
   Описать: размеры комнаты, положение мебели (лево/центр/право), источники света,
   планы (передний/средний/задний), лучшие ракурсы для съёмки.
   Сохранить описание в: refs/locations/[name]_geometry.txt

ОБЯЗАТЕЛЬНЫЙ ПОРЯДОК ВЫВОДА В ЧАТ:
1. Что нашёл в интернете (источники + детали)
2. Промпт который использовал
3. Картинка локации (Read file)
4. Геометрия которую ты сам описал глядя на картинку

ЗАПРЕЩЕНО вызывать Anthropic API для описания геометрии — ты видишь картинку сам.
ЗАПРЕЩЕНО пропускать показ картинки — она ВСЕГДА должна быть видна в чате.

После всех локаций — ОСТАНОВИСЬ. Напиши:
---
ЛОКАЦИИ ГОТОВЫ. Проверь картинки выше.
Напиши "продолжай" если всё устраивает.
---

### ЭТАП 1.5 — ОБЪЕКТЫ (правило ≥2 шотов)

**Принципиальное отличие от локаций:** для объектов **ВЕБ-ПОИСК НЕ
ДЕЛАЕМ**. Объекты — это бытовые/типовые предметы (смартфон, маркер,
чашка, сумка); генеративный AI знает как они выглядят. Описание из
ШАГ 1 уже содержит нужные детали.

Для каждого объекта которого нет в `refs/objects/`:

1. **Промпт сразу** — без веб-поиска. На основе описания из ШАГ 1
   составь промпт типа:
   ```
   <описание объекта>, on white background, product shot,
   soft even lighting, high detail, photorealistic, no people
   ```
   БЕЗ `cinematic`, БЕЗ `16:9` — для объектов лучше квадрат или
   вертикаль (1:1 или 3:4).
2. Запусти `pipeline.py generate <name> "<prompt>"` →
   картинка ляжет в `refs/objects/<name>.jpg`.
3. Прочитай картинку через Read tool, покажи юзеру.
4. **Геометрия НЕ нужна** — это объект, не локация. `<name>_geometry.txt`
   не создаётся.

После всех объектов — ОСТАНОВИСЬ. Напиши:
---
ОБЪЕКТЫ ГОТОВЫ. Проверь картинки выше.
Напиши "продолжай" если всё устраивает.
---

### ЭТАП 2 — СТОРИБОРДЫ
После команды "продолжай":
1. Читай геометрию из [name]_geometry.txt
2. Читай правила из instructions/PIPELINE_RULES.txt и instructions/Инструкция nano banana claude.txt
3. Составь монтажную карту с расчётом таймингов по формуле из PIPELINE_RULES.txt
4. Для каждого блока сцен пиши промпт сториборда
5. Сохраняй промпт в output/prompts/[ep_name]_block_N.txt — ОБЯЗАТЕЛЬНО с шапкой тегов
6. Запускай generate_storyboards.py для генерации картинок
7. После каждого сториборда — читай картинку через Read file и показывай в чате

### ВАЖНО — НИКАКОГО ТЕКСТА НА ШОТАХ
В промптах для шотов **НЕ пиши** строки `Text annotation below Panel N: "..."`.
Внутри картинки никакого текста, цифр, букв, аннотаций быть не должно.

Подписи (`SHOT N · Xs · описание`) накладываются автоматически программой
Storyboard Studio при экспорте сториборда в PNG. Это делает приложение
само, на основе данных из промпт-файла блока (parse_shots) — не модель.

Шапка промпта содержит правило `STRICT NO TEXT RULE` — не убирай его.

### Запросы на обновление geometry / описаний из приложения

Юзер может писать в чате фразы типа:
- `обнови geometry для prison_visitation` (или `update geometry for ...`)
- `онови geometry для prison_visitation` (украинский)

Это приходит **после того как юзер нажал «Перегенерировать» или «Изменить»**
на референс-карточке локации в Storyboard Studio. Картинка уже обновилась
на диске. Тебе нужно:

1. Открыть картинку через Read tool: `shows/<активный>/refs/locations/<name>.jpg`
2. Посмотреть глазами что на ней
3. Переписать `shows/<активный>/refs/locations/<name>_geometry.txt` под новую картинку
4. Кратко рапортовать юзеру что обновил

Это работает на любом из 3 языков. Старая geometry в файле — устарела, перезаписывай.

## ФОРМАТ ВЫВОДА — ВСЕГДА ТАБЛИЦА + ДЕТАЛИ БЛОКОВ (ОБЯЗАТЕЛЬНО)

Монтажную карту выводить в виде таблицы. После таблицы — ОБЯЗАТЕЛЬНО детали каждого блока.

Формат таблицы:

| Блок | Сцены | Шоты | Время |
|------|-------|------|-------|
| Блок 1 | 1–3 | 3 | 12с |
| Блок 2 | 4–6 | 3 | 14с |

После таблицы — детали каждого блока:

БЛОК 1 | Сцены 1–3 | 3 шота | 12с
  Сцена 1 (4с) — [краткое описание действия]
  Сцена 2 (4с) — [краткое описание действия]
  Сцена 3 (4с) — [краткое описание]. Реплика: "[текст реплики полностью]"

Правила детализации:
- Если в сцене есть реплика — писать её полностью после "Реплика:"
- Если нет реплики — только описание действия
- Время каждой сцены в скобках
- Реплики писать в двух версиях: сначала русский перевод, потом английский оригинал в скобках
  Формат: Реплика: "Русский перевод" ("English original")
  Время рассчитывать СТРОГО по английскому оригиналу — считать слова в английской версии

После деталей — список тегов:

**Теги:**
- [@]img1 = название_файла.jpg
- [@]img2 = название_файла.jpg
- [@]img3 = название_файла.jpg

## ФОРМАТ ФАЙЛА ПРОМПТА — ОБЯЗАТЕЛЬНАЯ ШАПКА (КРИТИЧЕСКИ ВАЖНО)

Когда сохраняешь промпт сториборда в файл output/prompts/[name].txt —
ВСЕГДА добавляй в самое начало файла шапку с маппингом тегов.

Формат шапки (строго такой):

# [@]img1 = название_файла_локации.jpg
# [@]img2 = название_файла_персонажа.jpg
# [@]img3 = название_файла_персонажа.jpg

Правила шапки:
- Порядок: сначала локация, потом персонажи (как в промпте)
- Имена файлов — точно как они называются в папках refs/
- Шапка идёт ДО тегов ===ПРОМПТ_БЛОК===
- БЕЗ этой шапки generate_storyboards.py не найдёт рефы и сгенерирует случайных персонажей

## ПРАВИЛА КОТОРЫЕ НЕЛЬЗЯ НАРУШАТЬ

**Anthropic API — НЕ ИСПОЛЬЗОВАТЬ:**
- Описание геометрии делать самостоятельно глядя на картинку в чате
- Промпты для локаций писать самостоятельно на основе веб-поиска
- Монтажную карту составлять самостоятельно по формуле из PIPELINE_RULES.txt
- Anthropic API используется ТОЛЬКО если pipeline.py явно его вызывает для Vision
- pipeline.py сейчас не использует Anthropic API — только Fast Gen AI

**Локации:**
- Одна локация = ОДНА картинка НА ВЕСЬ СЕРИАЛ, НАВСЕГДА
- Если локация уже есть в `refs/locations/` — использовать как есть, **не генерировать заново и не плодить варианты**
- ЗАПРЕЩЕНО создавать варианты типа `prison_visitation_v2.jpg`, `prison_inmate_side.jpg`, `kitchen_morning.jpg`, `room_from_window.jpg` — это одна и та же локация, реф один
- Один geometry-файл на локацию: `refs/locations/[name]_geometry.txt` живёт всё время сериала. В новой серии с той же локацией — читать СУЩЕСТВУЮЩИЙ geometry, не создавать новый
- Если локация переиспользуется в новой серии (та же тюрьма, та же кухня, та же квартира) — реф и geometry уже на месте, ничего перегенерировать не нужно. На ШАГЕ 1 пишу юзеру «✓ — реф уже есть».
- Ракурсы (общий план / средний / крупный, возле окна / возле кровати / через дверь, со спины / сбоку) описываются ТОЛЬКО в **промптах сторибордов для конкретного шота**. НЕ в geometry, НЕ в имени реф-файла, НЕ через создание нового рефа.
- Промпт локации (когда генерируем впервые) строится на основе веб-поиска — никогда не из головы

**Персонажи:**
- Никогда не описывать внешность словами — только тег референса
- Выбирать нужный файл одежды по контексту сцены
- Если рефа персонажа нет — сообщить пользователю и ждать

**Теги:**
- Среда всегда первая: [@]img1
- Объекты после среды
- Персонажи ВСЕГДА В КОНЦЕ

**Сториборды:**
- Максимум 4 шота на блок
- Максимум 15 секунд суммарно на блок
- Нумерация SHOT начинается с 1 в каждом блоке
- НИКОГДА персонажи не смотрят в камеру
- Эмоции только через микромимику — никаких "shocked", "angry", "disgusted"
